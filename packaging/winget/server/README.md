# Slipstream winget REST source

This directory contains a small read-only REST source for the Slipstream Windows host. It serves release manifests generated by build-data.mjs and does not expose an administrative API.

## Local use

~~~bash
npm install
npm run build
npm test
npm start
~~~

The service listens on PORT, which defaults to 3240. Set PF_WINGET_DATA to a generated data.json path when starting it. The health endpoint is /healthz.

~~~powershell
winget source add -n slipstream https://your-host.example/winget -t Microsoft.Rest
winget install vindeckyy.SlipstreamHost
~~~

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| GET | /information | Reports the source identity and supported protocol versions. |
| POST | /manifestSearch | Searches the generated manifest catalogue. |
| GET | /packageManifests/{id} | Returns the manifests for one package identifier and optional version. |
| GET | /healthz | Returns service health for a reverse proxy or container monitor. |

## Deployment

Put the service behind HTTPS. The winget client requires a publicly trusted certificate for a remote source. Bind the catalogue directory read-only and keep the service account limited to that directory.

The compose file is an example for a local deployment. Replace the bind-mounted data directory with the location used by your release process. Do not commit generated catalogue data that contains private URLs or credentials.

## Release data

By default, build-data.mjs reads release assets from the GitHub API for vindeckyy/slipstream. Set SLIPSTREAM_RELEASE_API and SLIPSTREAM_RELEASE_REPO for a mirror, or pass --local with a directory containing the checked-in manifest trio.

The generated catalogue is reproducible from release assets. Run the server tests after changing the response shape or the manifest merge logic.
